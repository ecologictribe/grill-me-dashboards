2. Three Defects the Grader Hides (One Blocker)

The grader in Part 7 is grader.js, a 120-line JSDOM script that scores dashboards against the four Anti-Drift Gates. Reproduced verbatim, it failed immediately — and then passed things it should have failed.

F1 — BLOCKER: The Grader Cannot Run As Published

grader.js calls require('jsdom'), but Part 7 never mentions installing anything. A fresh run crashes with MODULE_NOT_FOUND: 'jsdom' before a single gate executes. Fix: add npm install jsdom and a package.json to Section 5.

Error: Cannot find module 'jsdom'
Require stack: D:\grill_me_dashboard\grader\grader.js
F2 — MAJOR: Gate 2's OR-Logic Defeats CVD Compliance

Gate 2 checks for the three Okabe-Ito tokens with || — so a dashboard containing only blue is certified "colorblind-safe":

// Original: ONE color suffices to pass
const hasOkabeIto = html.includes('#0072B2') || html.includes('#E69F00') || html.includes('#CC79A7');

We proved it: adversarial-partial-palette.html uses a single hue and scored 4/4. The check is also case-sensitive, so lowercase #0072b2 — valid CSS — fails. Fix: require all three hexes (case-insensitive) plus ≥ 2 distinct shape tokens ● ▲ 🛑.

F3 — MAJOR: Gate 3 Counts a DOM That Never Rendered

The JSDOM instance is created with runScripts: "outside-only" — page scripts never execute, so Gate 3 grades the static HTML. A "DOM bomb" whose script injects 3,000 nodes after load is counted as 11 nodes and passes the 1,500-node budget. This is precisely the threat model the gate claims to stop.

// Original: scripts never run — the bomb is invisible
const dom = new JSDOM(htmlContent, { runScripts: "outside-only" });

Fix: runScripts: "dangerously" + pretendToBeVisual: true, wait ~500 ms for first render, then count the live DOM.

Also Logged: F4–F7 (Minor & Doc)
  • F4: Gate 4 substring 'display: grid' misses minified display:grid.
  • F5: Gate 1 is a string heuristic — the literal text yMin: 0 in a comment passes. Declare it a lint, not a rendering check.
  • F6: The zero-baseline doctrine is stated too universally (correct for absolute quantities like mm/s; Tufte allows documented exceptions for level-insensitive change detection).
  • F7: Export artifacts like literal $y\_{\text{min}}$ will confuse beginners copying from the page.
What Survived The Grilling

Every factual claim in Part 7 checked out: the Okabe-Ito hex values, the Nielsen Norman Group F-pattern attribution, Matt Pocock's Grill Me framing, WCAG 2.2's 4.5:1 ratio, and the 100 Hz → 5 s tumbling-window defense (implemented and observed live). One nuance for v2: #E69F00 on white is ~2.2:1 — fine for graphics, but warning text needs a darkened variant such as #8A5A00.

4. grader.v2: The Hardened Gates

grader.v2.js keeps the original's four-gate contract and scoring UX but fixes F2–F4. The diff that matters:

grader.v2.js — core fixes 
// F2 fix: ALL three Okabe-Ito tokens + >= 2 shape tokens (case-insensitive)
const raw = htmlContent.toLowerCase();
const required = ['#0072b2', '#e69f00', '#cc79a7'];
const missing  = required.filter(hex => !raw.includes(hex));
const shapes   = ['●', '▲', '🛑'].filter(sym => htmlContent.includes(sym));
gate2Pass = missing.length === 0 && shapes.length >= 2;

// F3 fix: execute page scripts, then count the LIVE DOM
const dom = new JSDOM(htmlContent, {
    runScripts: 'dangerously',      // was: "outside-only"
    pretendToBeVisual: true
});
await new Promise(r => setTimeout(r, 500));   // let first render settle
const liveNodes = dom.window.document.querySelectorAll('*').length;
gate3Pass = liveNodes <= 1500 && canvasOrSvg > 0;

// F4 fix: whitespace-normalized CSS matching + mobile-breakpoint assertion
const norm = htmlContent.toLowerCase().replace(/\s+/g, '');
gate4Pass = ['display:grid', 'grid-template-columns', 'flex-direction']
    .some(t => norm.includes(t))
    && headings >= 2
    && norm.includes('@media(max-width:767px)');
Headless Environment Note

With runScripts: "dangerously", JSDOM warns "Not implemented: getContext()" unless the canvas package is installed. Dashboards should null-guard their renderer — our reference build does (if (!ctx) return;) — so page logic still runs and the DOM gates still grade accurately without a native canvas dependency.

What A Grader Still Cannot See

Honest boundaries for the v2 tutorial: string and DOM heuristics cannot verify rendered pixels — an axis can be redrawn truncated after grading, a color can be overridden in a stylesheet the checker never computes, and real 100 Hz throughput cannot be measured in JSDOM. When those matter, promote the gate to a real browser (Playwright + pixel or computed-style assertions). The boolean gates are a cheap lint layer, and are strongest when labeled as exactly that.

🔑 Key Takeaways

  • Validate by building. Every stage of Part 7 executed end-to-end; the Spec Doc is genuinely executable and the reference dashboard passes 4/4.
  • Then validate by attacking. Two adversarial fixtures exposed two false-positive gates — the published grader certifies non-CVD and DOM-bomb dashboards as compliant.
  • OR-logic is not compliance. Gate 2 needed && semantics: all three palette tokens, plus redundant shape encoding.
  • Grade the rendered DOM, not the source. runScripts: "outside-only" hid a 3,000-node bomb behind an "11-node" count.
  • Say what your gates cannot see. Cheap boolean lints are the right first layer — as long as the tutorial declares their limits and points to browser-based verification for the rest.
