The Self-Grading Kit: Grade Your Dashboard in One Double-Click

🎯 What You'll Get

  • A one-file setup that installs everything the grader needs — you double-click, it handles the rest.
  • The ability to grade any HTML dashboard (yours or the reference) against the same 4 gates the trainer uses.
  • A screenshot-ready report to paste into your assignment PDF — the exact evidence Section B asks for.
  • Plain-English knowledge of what each gate actually checks, so a red ✗ never confuses you again.

🧰 What You Need (3 things)

  • A Windows, Mac, or Linux computer — the kit has a script for each.
  • Internet, once — the first double-click downloads the grader engine (~2 minutes). After that it works offline.
  • The course repo — click the green <> Code button on GitHub → Download ZIP → unzip it anywhere (Desktop is fine).

You do NOT need: to know what Node.js is, to open a terminal, to type any command, or to install Python/Power BI/anything else. The kit does all of that for you.

🚀 The 30-Second Path

1

Download & unzip the repo

On the GitHub repo page: green <> Code button → Download ZIP. Unzip it. You're looking for the folder that contains self-grade.bat.

2

Double-click self-grade.bat (Windows) — or run self-grade.sh (Mac/Linux)

A black window opens. The first time, it says "First-time setup: installing the grader engine" and takes ~2 minutes — that's the one-time internet step. On a Mac/Linux terminal: bash self-grade.sh.

3

Read your verdict

The window shows 4 gates, each with ✅ PASS or ❌ FAIL, and a final line: FINAL SCORE: X / 4 GATES PASSED. A copy is also saved as self-grade-report.txt inside the repo folder. Screenshot it for your PDF.

By default the kit grades the reference dashboard (a demo run so you can see a real 4/4). To grade your own report, see the next section — it's the same double-click.
Don't want to install anything at all?
There's a second grader that runs entirely in your browser — drop your HTML file onto the Eval Tool page and get the same 4-gate report, with a copy-ready text and a shareable result link. Same gates, same verdicts, zero setup. This .bat version stays useful offline and shows exactly what the browser tool runs under the hood.

📄 Grade YOUR Own Report

This is the part that matters for the assignment. You don't type anything — you drag and drop.

🖥️ Windows — drag & drop, no typing 
1. Open the unzipped repo folder in File Explorer
2. Find your-dashboard.html (it can live anywhere — Desktop, Downloads...)
3. Drag the file ON TOP OF self-grade.bat and let go
4. The kit opens and grades your file — that's it
🖥️ Mac / Linux — one extra word in the terminal 
bash self-grade.sh /path/to/your-dashboard.html

💡 On the optional Power BI path? The grader reads HTML files only — a .pbix is a binary project, not a web page, so no script can check it. Your equivalent evidence is the hand-checked gate screenshots described in the scorecard — doing those checks by hand is exactly why the Power BI path earns bonus marks.

The 4 Gates in Plain English

📏 Gate 1 — Baseline

Does every chart start its measuring axis at zero? Truncated axes exaggerate differences — the classic way charts lie. Fix: set your y-axis minimum to 0 (or state why not).

🎨 Gate 2 — Colour & Shapes

Can a colourblind colleague still read your series? Your palette must include the 3 colourblind-safe tokens and distinct shapes (● ▲ ■) so colour isn't the only signal.

⚡ Gate 3 — Speed

How heavy is your page after it finishes loading? Under 1,500 DOM nodes keeps the dashboard snappy on a lab PC or a phone. Heavy = slow = nobody opens it twice.

📐 Gate 4 — Layout

Is there a real grid, proper headings (so it reads top-left → down, like people scan), and a mobile breakpoint? A PDF print of a phone-screen mess fails here.

A FAIL tells you which decision drifted from your spec — not that you're bad at this. Each gate maps to failure modes you've studied: Part 1 (dishonest baselines), Part 2 (colour & cognition), Part 3 (layout & context loss). The full evidence for why the gates are shaped this way: VALIDATION.md.

🧯 Troubleshooting — If Something Goes Wrong

The 99% path is the double-click. If yours is the 1%, it's almost always one of these:

"Windows protected your PC" or "unknown publisher" blue box
Click More info → Run anyway. Windows says this about every .bat file from the internet — it's not a virus warning specific to this file. (You can also right-click the file → Properties → check Unblock → OK, then double-click normally.)
"node is not recognized" or the window closes instantly
Node.js isn't installed yet. Install the free LTS version from nodejs.org (Next → Next → Finish), then double-click self-grade.bat again. One-time step.
First-time setup stalls or says "Setup failed"
The grader engine (~2 min) needs internet. Check the Wi-Fi, close anything saturating it, and run the file again — it resumes cleanly. Campus networks sometimes block downloads: your phone hotspot always works. Still stuck? Ask the trainer to run self-grade.bat once on their machine — after that, everyone's copy of the repo works.
My dashboard scores below 4/4 — what now?
That's the kit working as intended: it found a drift between your spec and your pixels. Read the failing gate's line, fix that one decision, double-click again. Gates are boolean on purpose — there's no partial credit to negotiate, only a decision to correct. The Challenge-Grill Method shows how the gate was supposed to be derived from your spec in the first place.
Can I break anything by running this?
No. The kit only reads your HTML file and writes one text file (self-grade-report.txt). It never modifies your dashboard, your marks, or anything outside the repo folder.
