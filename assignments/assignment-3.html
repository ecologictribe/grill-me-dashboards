🕵️ The Red Team — Definition, Formation & Duties

What Is a Red Team?

Originating in security and engineering war-gaming, a Red Team is an independent adversarial audit group chartered to challenge assumptions, stress-test edge cases, and uncover where a system silently lies before it reaches real users. While the Blue Team (the dashboard authors) builds and defends the artifact, the Red Team actively tries to break it.

Formation & Cross-Pack Rules

  • Dual-Hat Classroom Model: Every student/pair plays Blue Team on their own Mystery Pack and Red Team on a different pair's dashboard.
  • Cross-Pack Matching: Pairs are matched across different packs (e.g., Alpha → Beta → Gamma → Delta → Epsilon → Zeta → Alpha) so the Red Team brings zero shared code or blind spots.
  • No Mutual Favours: Pair A never audits the same pair that audits Pair A (rotate in a ring: A → B → C → A) so scoring stays honest.

Team Composition (Roles Inside a Red Team)

  • Role 1 — Data & Logic Challenger (CSV Breaker): Mutates test CSVs (injects blank outage rows, duplicates, extreme outliers, >1,000 rows, shuffled order) to catch hardcoded data or broken math.
  • Role 2 — Visual & Governance Auditor (Trap Hunter): Tests 375px mobile layout, print/PDF export, colourblind (CVD) legibility, PII leakage, and Spec-to-Pixel drift.
  • Solo Students: Run both hats sequentially using the 4-check protocol below.

 What Is a "Curveball Presentation"?

                
Borrowed from baseball (a pitch that looks straight, then breaks sharply right before the plate), a Curveball Presentation means you do not present solely on the static CSV you practiced with all week. Mid-presentation on 20 Nov 2026, the trainer hands you a brand-new, unseen _v2_curveball.csv (same columns, mutated values—more outages, >2,000 rows, extreme outliers, or reversed order) to load live on stage.

                

                    

                        Why We Do This:
                        
    
                            
  • Exposes hardcoded AI HTML/charts immediately (numbers stay frozen).
    • 
                            
  • Tests whether Custom Gate #5 actually validates live parsed rows.
    • 
                            
  • Forces live sensemaking instead of memorized scripts.
    • 
                        

                    

                    

                        4 Possible Stage Outcomes (Logged in Peer Tool):
